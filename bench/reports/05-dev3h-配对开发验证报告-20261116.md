## 2. 问题根因与外置修复证据

### 2.1 缓存命中率问题（已由原生参数解决并在 `sd-dev3h-r1` 1K 输出复核）

- **原问题**：默认 SWA 池每 DP 仅 `30,208` token，无法同时容纳每 DP 8 条（全局 64 条）独立 128K 请求的前缀块尾部，导致 `align-p0-r2` 第二阶段命中率跌至 `14.03%–21.83%` 并退化为重 prefill。
- **采用方案**：原生参数 `MEM_FRACTION_STATIC=0.85` + `--swa-prefix-tails 384`（未启用实验性的 `SGLANG_ALIGN_FINISH_SWA_TRIM` 裁剪补丁）。每 DP SWA 池扩至 `165,376` token，每 DP 主 KV 为 `8,431,360` token（DP8 总计 `67,450,880` token）。
- **整模 1K 输出复核**：在 `sd-dev3h-r1-p0` 与 `sd-dev3h-r1-p1` 的 `64 × 128K -> 1K` 两阶段测试中，双侧 **64/64 请求均精确命中 `130,816` token（`99.79%`）**，且双侧均观测到 64 路并发流式输出的共同纯 decode 窗口（`14.72s` / `14.41s`）。

### 2.2 DeepInfer A2 Reader（U5）误差根因与 `repair-a2-reader` 设计

1. **为什么此前 `r2–r5` 探针未能复现 `audit64` 行为**  
   SGLang 在 `import sglang` 时才设置 `FLASHINFER_WORKSPACE_BASE=$HOME/.cache/sglang/.cache/flashinfer`，使 FlashInfer 命中校准表 `0.7.4/120f/autotune/sparse_mla_sm120_cpb.json`：在 `heads=64, topk=128, extra_topk=512, fp4=True` 下，`T=1..16` 与 `T=48` 均被路由至 **`variant=0`（`DECODE_SPLITK`），`cpb=3`**。此前独立脚本若先 `import flashinfer` 再 `import sglang`，会漏掉校准文件并退回 `cpb=1`，导致测速与误差基线失真。

2. **U5 精度劣化的真实数值根因**  
   在 FlashInfer 原生 `dsv41_bf16/decode.cuh` 中，`DECODE_SPLITK` 的每个 split CTA 在写回中间缓冲区 `mid_out` 时将 `float32` 局部归一化输出提前截断为 **`__nv_bfloat16`**，随后 `merge.cuh` 合并多个 split 后再次舍入为 `bf16`。在 `cpb=3`（10 个 chunk 切成 4 个有效 split）下，该二次 BF16 截断引入约 `+34%` 额外舍入噪声（`8×64` RMS `0.002128`，而无 split 的单 CTA 理论/实测值约为 `0.001586`），使得 A2 编码在与自身解量化缓存比对时被 split 边界截断噪声掩盖，出现 `+1.50e-6`（`0.00212784 -> 0.00212934`）的微小倒挂。此外，原生 `decode_grid` 按 `max_Splits=10` 启动了 6 个空转 CTA。

3. **外置隔离实现（`/data/bench/align/repair-a2-reader/`）**
   - `dsv41_bf16_fp32mid.cu`（SHA256 `3aef23b9705df16eda2e07fc4a8823c9aad06c03504a4e32df9548d52db7326a`）：直接 `#include` FlashInfer 原生 `dsv41_bf16/{types,load,mma,decode,merge}.cuh`，在 `SGLANG_DI_ALIGN_A2=1` 的 `DECODE_SPLITK` 路径复用双缓冲 `run_bf16_tiles` 流水加载，将局部输出直接写入 `float* mid_out_fp32`，在 `merge` 阶段完成单次 FP32 加权归约后再一次性转为 `bf16`，并按 `active_splits = ceil(chunk_capacity / cpb)`（`4` 个活跃 split 而非 `10` 个）发射网格，彻底消除空 CTA 开销与主机同步（100% CUDA Graph 兼容）。
   - `a2_fp32mid_reader.py`（SHA256 `c056c1577d9faf889079c2cfbabc1cb9247e181fae90e90a58824d1426ba9432`）：对 `variant != 0`（如 `rows >= 24, != 48` 的 `PREFILL_SG`）直接调用 `prepared._execute_fn(False)` 避免二次 Python 包装开销；`A2=0` 时完全透传原函数。
   - `sitecustomize.py`（SHA256 `296da87ba2143f8917f3765e78790f2c325716b429b11394b8ad4b349cc9b296`）：导入期仅依赖 Python 标准库（兼容系统 `/usr/bin/python3` 工具脚本），在首次导入 `sglang.kernels.ops.attention.dsv41_sm120` 时挂载惰性包装，自动覆盖主进程与全部 8 个 TP/DP 子进程。
